# NT36536 手写笔输入

`7.3.4-erhai-p7` 在设备树声明 `novatek,pen-support` 时默认启用笔扫描。
此前 p6 已包含笔坐标、压感、倾斜和按键上报，但 `pen_scan` 初始为 `0`，
因此仅注册 `NVTCapacitivePen` 并不代表控制器会扫描笔。

本次从参考内核原样移植
[`b6fa42deb71898af5fda6ad955004d1b73529abc`](https://github.com/yzddmr6/linux-sm8750-erhai/commit/b6fa42deb71898af5fda6ad955004d1b73529abc)，
在独立 `linux-sm8750-erhai-patchset` 的维护分支提交后导出，再用
`tools/vendor-kernel-patchset.py` 同步。原作者、日期及协作署名保留。
本项目的构建和运行不读取参考发行版工作区。

笔数据通过 NT36536 的 SPI 输入报告进入内核及 libinput；桌面识别为内置数位笔。
压力轴范围是 `0..16384`，不是对实际有效压感级数的测量。
扫描设置由现有驱动在面板重新上电、休眠恢复及 ESD 固件重载后恢复，
扫描命令失败会记录日志，不阻止手指触控。关闭面板时控制器仍按原路径休眠。
默认开启扫描可能增加亮屏功耗；本次未测量增量。

扫描开关仍可由管理员在运行时设置，不需重启，也不需重新加载驱动：

```sh
cat /sys/bus/spi/devices/spi*/pen_scan
printf '1\n' | run0 tee /sys/bus/spi/devices/spi0.0/pen_scan
# 临时关闭：将 1 改为 0；下次启动恢复默认开启。
```

`pen_scan=1` 表示驱动已请求扫描，不证明笔有电或已经产生输入。
笔充电、蓝牙配对／电量显示通过单独的 CPS8601 和 BlueZ 路径处理。
有输入问题时先确认笔型号兼容且有电，再检查事件，不能通过设备注册或轴范围宣称压感可用。

验收应同时检查：

- 新内核启动后、尚未手动写 sysfs 时，`pen_scan` 为 `1`，内核记录 `pen scan on`。
- `udevadm info -q property -n /dev/input/eventN` 对 `NVTCapacitivePen` 给出 `ID_INPUT_TABLET=1`。
- 用笔移动、轻压和重压时，`evtest /dev/input/eventN` 能看到坐标、`BTN_TOUCH` 和变化的 `ABS_PRESSURE`。
- 熄屏／亮屏及挂起／恢复后重复书写；临时关闭扫描再恢复也应可用。

实际 event 编号从 `/proc/bus/input/devices` 查找，不将 `event3` 作为稳定接口。
移植与构建证据见 `inputs/kernel-patchset/provenance/pen-scan-p7-*.json`。
实机验收状态另记，设备属性读取不能替代真实书写测试。

## p8 磁吸自动连接

蓝牙开启时，将 OnePlus Pencil 吸附到充电位置。CPS8601 校验充电线圈收到的地址，
系统服务尝试配对或连接这支笔，BlueZ 负责 HID 及电量上报。
可以通过 `hardware.oneplus-pad2pro.pen.autoConnect` 调整这一行为。

## p19 磁吸充电

p18 实机蓝牙可读取笔电量，但重新吸附后 CPS8601 未报告吸附事件，GPIO172 中断计数为零。
芯片有时在 ADSP 确认升压请求后仍返回 I²C `-ENXIO`。同一支笔在原厂 Android 下可以充电。
参考发行版 v0.12.1 固定的内核 `da4b783e34bd` 使用同一套 GPIO 与保护阈值。
其随包提供的固件与本机原厂 Android 镜像逐字节一致，版本为 `0x011e`。

临时模块先拉高唤醒线，再使能芯片电源，成功读出 `0x011e`。
芯片寄存器存在待处理的吸附标志。手动处理该标志后，驱动收到了 `hboost 160` 应答，
但 IRQ 脚保持低电平，未取得笔电量上报。原厂运行时设备树为 GPIO172 的工作态配置上拉。
p19 将该上拉加入设备树，在启动扫描时处理已经挂起的事件，并按 16 位读取停止供电原因。
用 p18 临时加载该设备树和驱动后，中断恢复，收到吸附和升压应答。该次吸附随后出现 `0x200`
异物检测，发射电流读数为零。原厂 Android 开机时也曾报告同一保护，重新吸附后用户确认可充电。
p19 通过严格重放、ARM64 交叉编译、CPS8601 回归检查、平板原生构建和 kShimC 暂存。
候选已加入启动菜单，p18 为默认。p19 的出厂阈值保持原值，实机充电量仍待验收。

2026-11-19 实机启动 p19。笔未吸附时，芯片报告 `0x011e`，GPIO172 配置为上拉且为高电平。
吸附后收到中断和 `hboost 160` 应答，发射电流读数短时达到 231，约 7 秒后触发 `0x200`，
电流回落至接近空载。120 秒采样未收到笔电量。诊断模块试验让升压请求跟随最终吸附状态。
取下笔并重新初始化后，`present=0`，ADSP 确认待机码 `100`。重新吸附后约 7 秒再次触发
`0x200`，电流回落，仍未收到笔电量。

读取本机 Android 的 `oplus_wireless_pen.ko` 后确认，原厂将 `0x003e` 作为 16 位故障原因，
在相关故障发生时拉高充电禁止线。临时诊断模块复现该动作并请求待机码 `100`，GPIO107
变为高电平，发射电压读数由约 8.04 V 降至约 5.03 V，但中断仍约每秒 70 次。
卸载诊断模块后，ADSP 确认 `hboost 0`。

原厂模块的 GPIO 映射显示，初始化结束时降低 GPIO106，再将 GPIO105 拉低
50 ms 后恢复高电平。p19 在对应阶段脉冲切换的是 GPIO56。在笔已吸附时，
临时模块采用原厂顺序，并在允许充电前读回过流、欠压、过压和异物检测阈值。
随后 60 个样本的发射电流读数在 191–296 之间，采样跨度约两分钟，
期间未出现 `0x0200`。笔端仍未报告电量，取下再吸附的验证也未通过。
试验模块已卸载，GPIO 改动只保留为本地诊断补丁。

## 2026-11-19 蓝牙恢复排查
