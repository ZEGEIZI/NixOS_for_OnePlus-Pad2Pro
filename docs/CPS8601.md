# CPS8601 可选固件报错修复

实机原日志连续五次报告：

```text
Direct firmware load for wireless_pen/24926/cps8601_firmware.bin failed with error -2
```

随后仍显示 `CPS8601 ready, fw 0x011e` 和 `scan armed`。该文件用于可选的充电芯片
固件升级；现有芯片已经运行原厂固件。缺少这个文件不等于芯片初始化失败。

修复使用内核为可选固件提供的 `firmware_request_nowarn()`，保留现有重试和升级逻辑。
不存在文件时只保留一条说明，真正的读取错误仍发出带错误码的警告。
补丁不增加 CPS8601 固件文件，也不改变电压、时序、GPIO、扫描或升级条件。

匹配的 CPS8601 模块由 Nix 从固定内核源码独立重建，通过 `boot.extraModulePackages`
加入对应代际。depmod 的明确覆盖规则选择 `updates/cps8601.ko`；离线已验证普通版和
诊断版都解析到此模块，版本为 `nixos-optional-fw1`，内核与已有实机验证版一致。
这是外置模块，内核可能记录正常的 out-of-tree module 标记；修复目标是重复的
可选固件加载失败，不是屏蔽所有内核警告。

普通版材料：`artifacts/nixos-pad2pro-install-v7/`，菜单 ID 为 `c5d38997…`。
只读诊断版：`artifacts/nixos-pad2pro-install-v7-debug/`，菜单 ID 为 `9bb09c19…`。
两个代际均已安装，全量 store 校验和实际六个启动条目的独立读取器检查通过；
原四代、Android boot_a 和 GPT 保留，分区已卸载。诊断代实机验证通过：实际加载 `nixos-optional-fw1`，重复固件缺失报错为 0，
芯片固件 `0x011e`，ready 和 scan armed 正常，失败服务为 0。普通当前代也已启动至登录提示，USB 与 SSH 主机身份验证通过，HTTP 诊断默认关闭。

验证使用真实驱动函数和模拟硬件回调，包括缺失、I/O 错误、截断、版本相同、
版本不同、强制升级、升级失败和短暂加载失败共 8 种情况。原函数可复现测试失败，
补丁后的 8 种情况均通过。离线测试不会操作真实充电硬件；实际笔充电效果仍未验收。
