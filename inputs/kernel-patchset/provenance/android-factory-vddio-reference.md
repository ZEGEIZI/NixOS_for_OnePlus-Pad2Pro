# XN242 VDDIO 原厂对照（2026-11-14）

已使用用户授权的 ADB Root 读取本机 Android 16 的生效设备树与亮屏调压器状态，
并从只读取得的 A 槽原厂 vendor_boot／dtbo 重建 DTB。
基树索引 6、overlay 索引 4 的 21 项相关属性与 Android 运行中的 DTB 一致。

| 项目 | 结果 |
| --- | --- |
| 实际面板 | XN242 / P_D / A0024，由启动参数选择，且 /proc/devinfo/lcd 对应 |
| 供电链 | dsi-display-primary → vddio-supply → ldob12 / pm_humu_l12 |
| 面板消费端请求 | min = max = 1,900,000 µV |
| 调压器初始化 | 1,900,000 µV |
| 原厂调压器约束 | 1,200,000–1,900,000 µV；这不是芯片绝对电气额定值 |
| Android 亮屏报告 | 1,900,000 µV，enabled，1 个使用者 |
| 主线 nldo515 模型 | 320,000 µV 起，8,000 µV 步进 |
| 1.900 V 相邻档位 | selector 197 = 1.896 V；198 = 1.904 V |
| 当前 p5 | 固定为 1.896 V，比原厂名义请求低 4 mV，约 0.21% |

原设备 Erhai DTS 已允许 1.896–1.904 V，并注释原厂请求为 1.9 V。
此次迁移在 Linux 7.3 的 RPMh 初始读回中观察到原始 1900 mV 被映射为 selector 198。
将约束固定到原有下方档位后，同一诊断内核成功上屏，随后正常原生系统也通过验收。
因此 1.896 V 的来源是主线驱动建模、既有设备配置及控制实验，不是原厂精确设定。

应区分“原厂请求 1.900 V”“驱动报告 1.900 V”“主线请求 1.896 V”和物理实测电压。
本次读取没有进行独立电压测量；此前实验也不能单独证明物理 1.904 V 过高导致重启，
初始化、读回取整与重新发送电压请求的作用仍需分别验证。

此次只采集参考，没有修改运行内核或电压。当前已验收的 1.896 V 仍有主线实机证据；
后续若要对齐 1.900 V，应先核对 PMIC 型号／电压模型与 RPMh 初始化语义，再另行构建验证。
